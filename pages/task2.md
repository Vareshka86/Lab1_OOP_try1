# Задание №2. Динамический массив и new/delete {#task2}

## Условие задания

Освоить `new`/`delete`, избежать «болтающихся указателей» (dangling pointers) и утечек памяти.
Написать программу для обработки одномерного динамического массива:

1. Спросить у пользователя размер массива N.
2. Выделить память под массив, используя `new int[N]{}`.
3. Написать функцию `void process(int*& arr, int size)`, которая принимает ссылку на указатель
   (чтобы можно было изменить сам указатель, если потребуется) и делает следующее:
   - находит первый отрицательный элемент;
   - если такой есть, создаёт новый динамический массив, копирует туда все элементы до
     отрицательного, а старую память корректно освобождает (указатель `arr` теперь должен
     смотреть на новый массив).
4. Вывести результат.
5. Освободить память и обнулить указатель (`arr = nullptr;`). Попытаться вывести значение по
   указателю после обнуления, чтобы продемонстрировать безопасное поведение программы.

## Как решено

Всё задание выполняет runTask2() — по шагам условия. Массив создаётся в ней:
`int* arr = new int[size]{};`, где `size` — число N, введённое пользователем (от 1 до 15).

| Функция | Что делает | Что демонстрирует |
|---------|------------|-------------------|
| findFirstNegative() | возвращает индекс первого отрицательного элемента или −1 | обход массива по указателю, проверка `nullptr` |
| process() | оставляет элементы до первого отрицательного: новый массив, копирование, `delete[]` старого | `new[]`, `delete[]`, ссылка на указатель `int*&` |
| printDynamicArray() | выводит индексы и значения; при `nullptr` выводит сообщение | безопасное обращение к памяти |
| freeArray() | `delete[] arr;` и `arr = nullptr;` | защита от «болтающегося» указателя |
| runTask2() | шаги 1–5 условия | выделение и освобождение памяти, обработка прерванного ввода |

Новый размер массива `process()` вернуть не может: по условию размер передаётся в неё по
значению. Поэтому runTask2() узнаёт его заранее той же функцией findFirstNegative(), которой
пользуется `process()`.

Случайные числа для заполнения массива даёт общий модуль `random_number` (функция randomInt()),
им же пользуется Задание №1.

Код задания: task2.h (объявления и документация), task2.cpp (реализация).

## Динамический массив: new[] и delete[]

Размер статического массива должен быть известен при компиляции. Здесь N вводит пользователь,
поэтому память выделяется во время работы программы:

```cpp
int* arr = new int[size]{};   // массив из size элементов, {} обнуляет все элементы
// ... работа с массивом arr[0] ... arr[size - 1]
delete[] arr;                 // освобождение: для массива - именно delete[], а не delete
```

Память, выделенная через `new[]`, сама не освобождается: если «потерять» указатель на неё и не
вызвать `delete[]`, получится **утечка памяти**. Поэтому в `process()` старый массив
освобождается сразу после копирования, а в конце задания — через freeArray().

По указателю на динамический массив цикл range-based for не работает (компилятору неизвестен
размер), поэтому элементы перебираются обычным циклом с индексом от `0` до `size - 1`.

## Ссылка на указатель int*&

```cpp
void process(int*& arr, int size);
```

Если бы параметр был `int* arr`, функция получила бы **копию** указателя: присваивание
`arr = newArr` изменило бы только копию, а у вызывающей стороны остался бы старый адрес — уже
освобождённой памяти. Со ссылкой `int*&` переменная `arr` внутри функции — это и есть указатель
вызывающей стороны, поэтому после `process()` он смотрит на новый массив. В примере работы ниже
это видно по адресам: до вызова `0x16d797dab60`, после — `0x16d797d44c0`.

## «Болтающийся» указатель и nullptr

После `delete[] arr` указатель по-прежнему хранит старый адрес, хотя память уже освобождена.
Такой указатель называется «болтающимся»: обращение по нему — неопределённое поведение.
Поэтому freeArray() сразу обнуляет указатель:

```cpp
void freeArray(int*& arr)
{
    delete[] arr;   // для nullptr ничего не делает - повторный вызов безопасен
    arr = nullptr;  // указатель больше не хранит адрес освобождённой памяти
}
```

Шаг 5 условия — попытка вывести массив после обнуления. printDynamicArray() перед обращением к
элементам проверяет `arr == nullptr` и вместо чтения памяти выводит сообщение, поэтому программа
не падает.

## Защита от ошибок

- **Размер N** читается через readIntInRange(): допускается только целое число от 1 до 15
  (при 15 элементах строка массива помещается в окне консоли). «abc», «2.5», 0 и 16 отклоняются.
- **Нет отрицательных элементов** — `process()` ничего не меняет: ни массив, ни указатель.
- **Отрицательный элемент первый** — новый массив пустой: `new int[0]` в C++ разрешён, но
  к его элементам не обращаемся; printDynamicArray() выводит «Массив пуст».
- **Прерванный ввод** (конец потока при вводе элементов) — runTask2() перехватывает исключение,
  освобождает память через freeArray() и передаёт исключение дальше в `main`: утечки нет.
- **Проверка на утечки.** Отдельная тестовая программа подменяла операторы `new[]` и `delete[]`
  счётчиком: после каждого случая (отрицательный в середине, первым, отрицательных нет, `nullptr`,
  двойной вызов freeArray()) число неосвобождённых массивов возвращалось к нулю.

```

Индекс   :      0      1      2      3      4      5
Значение :      0      0      0      0      0      0

Как заполнить массив?
  1 - случайными числами от -50 до 50
  2 - вручную с клавиатуры
Ваш выбор: 2
Введите 6 целых чисел:
  arr[0] = 5
  arr[1] = 3
  arr[2] = -2
  arr[3] = 7
  arr[4] = -1
  arr[5] = 4

Исходный массив:
Индекс   :      0      1      2      3      4      5
Значение :      5      3     -2      7     -1      4

Шаг 3. process(arr, size): первый отрицательный элемент arr[2] = -2.
Создан новый массив (элементов: 2), старая память освобождена (delete[]).

Шаг 4. Результат:

Значение :      5      3

Указатель равен nullptr: массива нет, к памяти не обращаемся.
```
